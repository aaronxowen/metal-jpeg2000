# proto/ — GPU/Metal JPEG 2000 decode prototype

Validation-first prototype for the feasibility study (see `../FEASIBILITY.md`). Each decode stage was
ported from OpenJPEG to a portable-C reference, then to a Metal kernel, and validated bit/integer-exact
against an OpenJPEG-derived oracle.

## Files by stage

| Stage | Reference (C) | Metal kernel | Benchmark/harness | Validation |
|---|---|---|---|---|
| Tier-1 (MQ/EBCOT) | `t1_ref.c` | `t1_kernel.metal` (+`t1_luts.metal`) | `t1_bench.swift` | bit-exact |
| Inverse 9/7 DWT | `dwt_ref.c` | `dwt_kernel.metal` | `dwt_bench.swift` | float-exact |
| Back-end (iDWT+ICT+shift) | `backend_ref.c` | `backend_kernel.metal` | `backend_bench.swift` | integer-exact |

Support: `gen_luts.py` generates `t1_luts.metal` from `../src/lib/openjp2/t1_luts.h`.

## Corpora (gitignored — derived data, ~115 MB)

Generated by env-gated dumps in the instrumented OpenJPEG (decode with `-threads 1`):

| File | From hook | Env var |
|---|---|---|
| `corpus.bin` | `t1.c` `opj_t1_decode_cblk` | `OPJ_T1_DUMP` |
| `dwt_corpus.bin` | `dwt.c` `opj_dwt_decode_real` | `OPJ_DWT_DUMP` |
| `backend_corpus.bin` | `tcd.c` `opj_tcd_decode_tile` | `OPJ_BACKEND_DUMP` |

## Build/run

GPU benches are standalone (no OpenJPEG build needed) — they only need the corpus files. See
`M1_RUNBOOK.md` for exact commands. Metal must be compiled **fast-math off**; C references with
**`-ffp-contract=off`** (to match OpenJPEG's non-fused NEON path).
